# VibeDraw 性能设计

VibeDraw 在 HermitApp 中直接运行原生 HTML、CSS 与 JavaScript，不依赖构建器。性能优化必须保留同一份可编辑画布数据、历史作品格式、模型请求语义和现有界面。

## 热路径

- 绘制与选择事件先合并到下一动画帧，避免一次触摸采样触发多次绘制。
- 已提交对象绘制到离屏内容层；正在落笔时只把当前笔画叠到缓存内容上。移动、缩放和图层变化才使内容层失效。
- 笔画边界使用 `WeakMap` 缓存，并在移动、缩放或追加点时精确失效。命中测试先检查边界，再检查线段。
- 图片解码请求按源地址合并；画布图片缓存最多 16 项或估算 48 MB 解码像素，持久化图片缓存最多 10 项或估算 24 MB UTF-16 字符串。当前画布正在使用的图片由对象持有，不会因缓存淘汰而闪烁。
- 调色后的生成结果按图片对象和调色参数复用，避免每次合成都重复执行锐化像素运算。
- 撤销记录使用结构化画布快照，不再通过 JSON 往返复制；最多保留 60 步或估算 12 MB。

## 存储与历史

- 未变化的画布不会重复写 Hermit 数据；写失败不会更新成功指纹，下次保存仍会重试。
- 可编辑数据使用 UTF-8 安全的 30 KB 分块，四路并发读写。该大小为 Hermit 64 KiB 物理记录保留 JSON 转义空间。
- 历史标题迁移只在配置 schema 升级时执行一次，不在每次启动扫描所有作品。
- 历史列表先呈现卡片，缩略图只在接近可视区域时加载；不支持 `IntersectionObserver` 的环境使用两个顺序工作器。
- 图片文件分块最多四路并发读写，缓存有明确上限，清理仍按存活作品引用判断。

## 模型输入

每次生成仍重新合成当前画布，保证参考图不是旧缓存。蒙版只为实际消费它的 OpenAI Images 或 SD WebUI 接口编码；A1X、ComfyUI、Stability 和高质量渲染不再做无用的双份 PNG 蒙版编码。

## 诊断与回归

开发控制台可读取：

```js
vibedraw.components.canvas.performance()
vibedraw.services.assets.performance()
```

前者返回帧数、内容层重建次数、累计绘制对象数、图片缓存和撤销栈规模；后者返回资产缓存与正在进行的图片任务数。

运行回归检查与可重复基准：

```sh
node tools/verify.mjs --source-only
node tools/performance-benchmark.mjs
```

基准只报告当前机器上的相对数据，不以易波动的耗时作为测试通过条件。`tests/performance.test.mjs` 只验证稳定不变量：按帧合并、缓存上限、Unicode 分块和快照隔离。
